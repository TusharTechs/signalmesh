# Five-minute demo — reproduction guide

Anyone can re-run the exact sequence we present. `./scripts/demo.sh` paces every
step; each failure is a single endpoint call that auto-restores.

```bash
make infra                 # NATS
./scripts/dev-cluster.sh   # 3 nodes + load balancer
make dashboard             # http://localhost:3000 — keep on screen
./scripts/demo.sh
```

Each section below lists **what is injected**, **what the system does**, and
**what to verify on screen** — so the claims are checkable, not just narrated.

---

## 1 · Baseline (~40s)

**Injected:** nothing. 20 requests at concurrency 5 through the load balancer.

**Verify:** 3/3 nodes alive, both providers `HEALTHY` with quorum
(`observations: 3`), flat p95, 100% success.

> AI systems don't fail like normal web services. A dependency can return HTTP
> 200 and still be unusable, too slow, too expensive, or unsafe to trust.
> SignalMesh is the distributed reliability and attention control plane for AI
> agents.

---

## 2 · Semantic degradation

**Injected:** `semantic-degradation` — the primary returns **HTTP 200** with a
body that violates the response contract.

**System response:** contract-failure rate climbs, consensus health flips to
`UNHEALTHY`, routing moves traffic off the primary.

**Verify:** `contract_failure_pct > 0`, provider badge turns red, response
header shows `X-SignalMesh-Provider: local-fallback`.

> The provider is still returning 200. The body is wrong. **HTTP success is not
> AI success** — and this is the failure mode no existing health check sees.

---

## 3 · Provider outage

**Injected:** `provider-outage` — 100% error rate on the primary.

**System response:** circuit breaker opens, traffic shifts to the zero-cost
local path.

**Verify:** circuit state `OPEN`, requests still returning 200, `fallback_total`
climbing. Measured: 100 requests during a full outage, **zero failures**.

---

## 4 · Node failure

**Injected:** `node-failure` on node-b — the node stops emitting heartbeats.

**System response:** the cluster ages it out on heartbeat TTL, drops its
observations from the consensus count, and keeps serving.

**Verify:** node-b turns red, provider `observations` drops 3 → 2, quorum holds,
traffic uninterrupted.

*A hard `kill -9` on the node process produces the identical reaction — worth
showing if asked.*

---

## 5 · Agent retry loop

**Injected:** `agent-loop` — one agent retries an identical failing high-risk
call.

**System response:** request-fingerprint detection trips the breaker, opens a
`CRITICAL` incident, and raises a human escalation.

**Verify:** incident type `AGENT_LOOP`, reason codes `AGENT_LOOP_DETECTED` +
`RUNAWAY_RETRY_STOPPED`, recommended action
`HUMAN_REVIEW_BLOCK_AUTOMATIC_ACTION`.

> This is the failure that shows up as a bill, not an alert. We stop it in three
> attempts.

---

## 6 · Traffic spike

**Injected:** `traffic-spike` — a burst of background-class load.

**System response:** per-class bulkheads and bounded queues shed non-critical
traffic; critical capacity is untouched.

**Verify:** `BACKGROUND` dropped count climbing while `CRITICAL` dropped stays
at 0.

---

## 7 · Risk and economics

**Injected:** a per-agent budget of $0.00005.

**System response:** low-risk work routes to the zero-cost fallback; high-risk
work with no *safe* provider escalates rather than acting.

**Verify:** low-risk → 200 on `local-fallback`; high-risk → `BUDGET_EXHAUSTED` +
`HUMAN_ATTENTION_REQUIRED`, action blocked.

> High risk with no safe route doesn't get a degraded answer. It gets a person.
> **We route attention, not just requests.**
